# ProctorCode guide

## What it is

- A website for proctored coding tests.
- Admins create tests and review results.
- Candidates take the tests in the browser while the webcam and page activity are checked.

## Features

- Timed tests with a code editor (10 languages; JavaScript can be run in a safe sandbox).
- Webcam checks for "no face", "two faces" and "looking away". They run inside the browser.
- Flags for tab switches, leaving fullscreen, copy / paste and dev tools.
- A live integrity score. The test ends when it reaches 0.
- Admin reports: score, flag timeline and the submitted code.
- Invite links, so only people you choose can sign up.
- A public demo mode with "Try" buttons and a read-only demo admin.

## How to use

### For admins

1. Sign in with your admin email and password.
2. **Tests → New test.** Add a title, language, time limit, problem text (Markdown) and starter code.
3. **Invites → Create invite.** Copy the link and send it to candidates.
   - The link is shown once. Make a new one if you lose it.
   - Leave the email empty to share one link with a group (set "How many sign-ups").
4. **Sessions.** Open a report to see the score, each flag with its time, and the code.
5. Optional:
   - **Delete session** lets a candidate retake a test.
   - **Invites → Candidates → trash icon** deletes a candidate and all their data.
   - **Allow open sign-up** lets anyone create a candidate account.

### For candidates

1. Open the invite link and create your account.
2. Pick a test and read the rules. Tick the box to agree.
3. Allow the camera. The test opens in fullscreen.
4. Write your code and press **Submit**. Each test can be taken once.

## Run it yourself locally

Needs Node.js 22.13 or newer.

```bash
npm run setup     # install everything
npm run seed      # sample tests + dev accounts; prints fresh passwords
npm run backend   # API on http://localhost:4000
npm run frontend  # app on http://localhost:5173 (second terminal)
```

- Or set your own admin in `backend/.env` (copy `backend/.env.example`).
- Production build: `npm run build`, then `npm start` (serves everything on port 4000).

## Deploy on Render

`render.yaml` is the **free public demo**. Set these in Render → your service → **Environment**:

| Name | Value |
| --- | --- |
| `ADMIN_EMAIL` | Your email. |
| `ADMIN_PASSWORD` | 12+ characters, not a common password. |
| `DEMO_MODE` | `true` for the public demo. Remove it for real use. |
| `JWT_SECRET` | Already generated by Render. Leave it. |

- Without `ADMIN_EMAIL` / `ADMIN_PASSWORD` the site still runs, but has no admin.
- A weak `ADMIN_PASSWORD` or a short `JWT_SECRET` stops the app from starting (check the logs).
- **Free plan:** the disk is temporary. All data is lost on every restart, sleep and deploy.
- **Real use:** use `render.production.yaml`. It adds a paid plan and a disk at `/var/data` (`DATA_DIR`), so data is kept.

## Keep it safe

- Never share the admin password. Never commit `.env` files.
- Don't run real tests on the public demo: anyone can view demo data as the demo admin.
- Keep sign-up invite-only unless you really need open sign-up.
- Use HTTPS (Render does this for you). The camera needs it.
- What is stored: names, emails, password hashes (bcrypt), code, flags with times, scores.
- What is **not** stored: no video, no photos, no audio. They never leave the candidate's browser.

## Maintain it

- **Update:** run `npm update --prefix backend` and `npm update --prefix frontend`, then `npm audit` in each.
- **Tests:** `npm test` (API tests) and `npm run build` (frontend check). GitHub runs both on every push.
- **Back up:** copy the database file (`$DATA_DIR/app.db`) while the app is stopped, or use Render's disk snapshots.
- **Rotate `JWT_SECRET`:** set a new random value (32+ characters) and redeploy. Everyone is signed out.
- **Reset the admin password:** set a new `ADMIN_PASSWORD` and redeploy. Old sessions are signed out.
  - Or, when you know it, change it in the app (click your initials → Change password).

## Troubleshooting

- **Deploy failed, "ProctorCode will not start" in the logs:** a setting is unsafe or missing. The log line says which one. Render keeps the previous version running until you fix it.
- **Login page says "no admin yet":** set `ADMIN_EMAIL` and `ADMIN_PASSWORD`, then redeploy.
- **"Too many failed sign-in attempts":** wait 15 minutes, or sign in from another network.
- **Camera blocked:** allow the camera in the browser's site settings, and use HTTPS.
- **Data is gone on Render:** that is the free plan. Use `render.production.yaml` with a disk.
